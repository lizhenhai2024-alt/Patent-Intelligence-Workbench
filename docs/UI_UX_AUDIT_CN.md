# 中文界面与页面布局审计

## 设计方向

本产品服务于悬架与减振器研发人员，界面采用“工程证据控制台”而非通用聊天界面：导航稳定、数据密度可控、每一步都能回到公开件与本地证据。中文是默认工作语言；专利号、国家代码、DOCDB、INPADOC、PDF、EPO OPS 等标准专有名词保留原写法。

## 全局规则

- 左侧导航按工程工作流排列：检索、阅读、专利族、监控、专利库、技术分类、证据、工程情报、设置。
- 每页只保留一个强调按钮作为当前主动作；导出、打开外部页面、复制等放在次级操作区。
- 表格上方给出当前数据状态或操作提示，避免“空表格 + 不知道下一步”的情况。
- 外部 AI、翻译和 EPO OPS 配置明确说明数据去向与保存边界，不把配置行为伪装成分析结果。

## 页面审计与改造

| 页面 | 主要任务 | 调整后的布局逻辑 |
| --- | --- | --- |
| 专利检索 | 进入研究链路 | 顶部概览说明本地数据状态；条件区只保留检索必填项；结果表提供进入阅读、专利族和证据采集的明确下一步。 |
| 专利阅读 | 理解一件公开件 | 顶部显示来源与操作，主体保持原文、译文和附图的分栏关系，避免用英文栏目打断阅读。 |
| 专利族 | 以专利族为分析单位 | 输入、族类型、解析/入库/下载形成一条线；成员表与下载状态分开，避免将过程状态混在结果中。 |
| 专利监控 | 管理规则并复核变更 | 先选择规则，再修改周期或立即运行；规则与运行记录分别呈现，状态文本全部中文。 |
| 本地专利库 | 复用已保存资产 | 将“目录与同步”和“筛选、导出”拆为两行；选中专利后的阅读、专利族、PDF、目录动作集中在表格上方。 |
| 技术分类 | 选择可检索工程节点 | 分类树是唯一主视觉；只有叶节点可进入检索，并在状态栏解释原因。 |
| 证据中心 | 审阅网页、PDF、Office 采集结果 | 筛选项有明确中文标签；左侧结果、右侧预览，空状态直接说明从哪里创建首条证据。 |
| 工程情报 | 将本地专利转为可复核任务 | 任务说明、数据就绪度、所需输入、结果、可选 AI 解读依次呈现；空库不产生伪分析。 |
| 设置 | 管理可选外部服务与本地数据 | EPO OPS、翻译、本地数据分区；凭据保存位置与外发边界写明。 |

## 验收标准

1. 面向用户的导航、页标题、按钮、空状态、提示和配置字段均为中文；标准名称、专利号和 URL 除外。
2. 页面不改变 Search → Reader/Family → Download → Watch → LocalLibrary → Export 的核心工作流。
3. 术语不会改变 Family、公司实体、来源和证据的既有数据语义。
4. README 与桌面界面、RC.5 下载方式及 AI 数据边界一致。
